## Delivery reliability — 8 September 2026

Read the product CURRENT-WORK.md index in this directory or its parent before new work when it exists, and update it after accepted delivery. Use the existing repository and accepted assets; do not create a parallel replacement product.

Deliver the actual result with a link, relevant verification, unresolved limitations and the next action. Distinguish mock/local/preview/live status. Inspect rendered visuals at the intended screen size, check overlap/alignment/contrast, and play exported video/audio before handing it over. For product changes verify the affected real user journey; do not claim a skipped check passed.

Use existing release and permission rules. This guide does not authorize publication, production deployment, deletion, spending or account changes. Apply valid explicit authorization without unnecessary repeat questions, while honoring tool-required confirmations.

Identify the directory and owning task behind every preview URL; prevent Rewards/Hub/CMS or different products from accidentally sharing a server. Record resources deliberately left running. Close only disposable resources created by this task when they are no longer needed; do not stop other tasks or user previews.

For recurring work, consult the existing ledger first, do only due/changed work, preserve required verification deadlines, limit equivalent failed attempts to two per run, and retain the recovery condition for subsequent checks. Record authoritative publication evidence and check for duplicates before retrying uncertain actions.
